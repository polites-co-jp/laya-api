# チャットの使い方

**日本語** | [English](../en/chat.md) ・ [← README](../../README.md)

判断チャットは、Laya に文章と質問を渡して、どう判断するかをブラウザで確かめるための画面。
Laya は文章を生成するモデルではなく、与えた質問に「はい/いいえ」「どれか1つ」「何段階目か」を確率付きで答える判断モデルなので、チャットも「文章（state）を送ると、用意した質問への答えが返る」形になっている。

![判断チャットの画面](../images/chat-ja.png)

## 開く

1. [Docker コンテナ展開手順](deploy.md) に沿って起動する。チャットは `.env` に `COMPOSE_PROFILES=dev` があるとき（`.env.example` の既定）だけ起動する。
2. ブラウザで <http://127.0.0.1:22301> を開く。

チャットはサーバ側で API の署名を代行するので、ブラウザに秘密鍵は渡らない。
その代わり、チャットに届く人は誰でも API を使えるため、チャットは `127.0.0.1` にだけ公開している。

## 画面の構成

| 場所 | 内容 |
|---|---|
| ヘッダ右のステータス | Laya の状態。`Laya ready ・ cpu ・ english, multilingual` なら、CPU で english と multilingual を読み込み済み |
| ヘッダ右のボタン | 表示言語の切り替え（日本語 / English）。初回はブラウザの言語に合わせる |
| 左 | やりとりの記録と、判断させる文章の入力欄 |
| 右 | モデルの選択、質問の編集、メタデータ |

## 基本の流れ

1. 右の欄で質問を決める（最初は例題が3つ入っている）。
2. 下の入力欄に、判断させたい文章を書く。
3. 「送信」を押す（Ctrl+Enter でも送れる）。
4. 質問ごとの答えと確率が返る。

## 質問を作る

「＋ noul」「＋ choice」「＋ score」で質問を足し、× で消す。各質問は次の3つの欄からなる。

| 欄 | 内容 |
|---|---|
| 質問 ID | 結果の見出しになる名前。英数字と `_` `.` `-` で64文字まで。重複不可 |
| instructions | 何を判断させるかを文章で書く（例「今日中の対応が必要か？」） |
| criteria | 答えの候補。書き方は型ごとに違う（下表） |

| 型 | 聞けること | criteria の書き方 | 例 |
|---|---|---|---|
| noul | はい / いいえ | 任意。1行目に true の意味、2行目に false の意味 | `当日中の返信が必要`<br>`通常の順番で問題ない` |
| choice | 選択肢から1つ | 1行に1つ「ラベル: 説明」（2〜100個）。説明を省くとラベルがそのまま説明になる | `returns: 返品・破損`<br>`delivery: 配送状況` |
| score | 段階評価 | 1行に1つ、低い→高い順にラベル（2〜32個） | `Routine`<br>`Soon`<br>`Today` |

「質問を初期状態に戻す」で例題に戻る。

## 文章（state）を書く

入力欄に書いた文章が、そのまま Laya の `state` になる。
`{` か `[` で始まる正しい JSON を書くと、文字列ではなく JSON として送る（構造化されたデータを判断させたいとき）。

## モデルを選ぶ

| 選択肢 | 内容 |
|---|---|
| 自動（言語で振り分け） | Laya が文章の言語を見て english か multilingual を選ぶ。通常はこれでよい |
| english | 英語用のチェックポイント（ModernBERT-large ベース） |
| multilingual | 100以上の言語に対応するチェックポイント（mmBERT-base ベース）。日本語はこちら |
| typed-decisions | 4つの定型業務（カスタマーサービス、請求書処理、セキュリティインシデント、エージェントの実行記録）向けに追加学習したチェックポイント。自動では選ばれない。既定では起動時に読み込まないので、初回は取得と読み込みで時間がかかる |

## 結果を読む

| 型 | 表示 | 読み方 |
|---|---|---|
| noul | 「はい」または「いいえ」と、true の確率 | true の確率が 50% 以上なら「はい」 |
| choice | 最も確率の高い選択肢と confidence | 棒グラフが各選択肢の確率 |
| score | 最も確率の高い段階と、score・confidence | score は段階番号（0 始まり）の期待値。例: 4段階で 2.27 なら3段階目（Today）寄り |

各返答の下の行には、使われたモデル（`model: multilingual` など）、往復の時間、入出力トークン数、Laya での推論時間が出る。
「生のJSON」を開くと、API の応答をそのまま見られる。

## メタデータ

「メタデータ（任意）」を開くと `session_id` と `user` を入れられる。入れた値はリクエストにそのまま載せて Laya へ渡す。

## 保存されるもの

質問・モデル・メタデータ・表示言語はブラウザ（localStorage）に保存され、開き直しても残る。やりとりの記録は保存しない。

## エラーが出たとき

| 表示 | 原因 |
|---|---|
| 送信前に赤枠で出るメッセージ | 質問の書き方が正しくない（ID の重複、choice の選択肢が1つだけ など）。メッセージに従って直す |
| `エラー 413` | 上限を超えた（質問が多すぎる、文章が長すぎる など）。上限は [API 利用手順](api.md#6-ステータスコードと上限) |
| `エラー 422` | Laya が質問の形式を受け付けなかった。生の JSON の `detail` に理由がある |
| `エラー 502` / 右上が「Laya に接続できません」 | Laya の起動中。しばらく待つ |
| `エラー 503` | 同時リクエストが多すぎる。少し待って送り直す |
