# メール返信要否の判定の検証

メールの文面を入力し、受信者が「返信する必要がある / ない / どちらとも言えない」をモデルに判定させ、正解ラベルと比べて精度を測る。
仕組みは [誹謗中傷判定の検証](defamation-eval.md) と同じ（同じ質問をどのモデルにも送り、3つの選択肢の確率を比べる）。方針は [決定事項 D-13](decisions.md)、スクリプトと実行手順は [apps/reply-eval](../apps/reply-eval/README.md)。

## データ

日本語のメールで返信要否の正解が付いた公開データセットは見つからなかった。英語では Enron のメールに「返信を期待しているか」を注釈したもの（Sappelli ら 2016）があるが、ライセンスの記載がなく、元のメールとの突き合わせも要る。
そのため、架空の日本語メール300件を、この文書の判定基準に沿って正解ラベル付きで生成した（Claude のサブエージェント6つが、メールの種類ごとに分担）。人名・会社名・アドレスはすべて架空で、アドレスは `example.*` ドメインにした。
架空のデータなので、本文を含めてすべてリポジトリに置く。

生成したラベルの揺れを測るため、生成に関わっていない別のエージェントが、正解を伏せて本文だけから付け直した（二重ラベル）。一致率は [report.md](../apps/reply-eval/report.md) に出す。

## 判定基準

### 受信者

受信者は **山田 花子**（株式会社サンプル商事 営業部 主任）。仕事のメールも私用のメールも、この人の受信箱に届いたものとして判定する。
メールの先頭には `件名:`・`差出人:`・`宛先:`（To）・`CC:` の行があり、山田が To にいるか CC にいるかは本文から読み取れる。
宛先が「全社員」「営業部 全員」などのメーリングリストのときは、山田もその一員として To で受け取ったものとする（300件中16件）。

### 3つの区分

| 区分 | ラベル | 基準 |
|---|---|---|
| 返信が必要 | `reply_needed` | 受信者に向けた質問・依頼・確認・日程調整・承認依頼・出欠確認があり、メールで返事をしないと相手が困る、または返事を待っている。疑問符がなくても（「ご都合をお知らせください」「ご承認お願いします」）、文面がくだけていても（「明日いける？」）含める |
| 返信は不要 | `no_reply_needed` | 通知・自動送信・メールマガジン・広告、一斉送信の周知、CC での共有、こちらの質問への回答で完結しているもの、お礼や報告で完結しているもの、「返信不要」と書かれているもの。行動（フォームへの入力・支払い・確認）を求めていても、メールでの返事を求めていなければここに入れる |
| どちらとも言えない | `uncertain` | 返事が礼儀として望ましい程度で、なくても相手は困らない（「何かあればご連絡ください」「近況報告です」）。または、本文だけでは受信者が返事をすべき立場か分からない（CC にいる受信者に向けたとも、To の人に向けたとも読める質問） |

### 境界の例（架空の文）

| 文面の要点 | 区分 | 理由 |
|---|---|---|
| 「来週の打ち合わせ、火曜か木曜でご都合いかがでしょうか」（To: 山田） | reply_needed | 日程調整で、返事を待っている |
| 「資料を共有します。ご確認ください」（To: 山田、質問なし） | no_reply_needed | 共有で、返事は求めていない |
| 「ご注文の商品を発送しました」（自動送信） | no_reply_needed | 通知 |
| 「アンケートにご協力ください（フォームの URL）」 | no_reply_needed | 行動は求めるが、メールの返事は求めない |
| 「ご質問の件、在庫は3個です」（こちらの質問への回答） | no_reply_needed | 回答で完結している |
| 「出欠を今週中にこのメールへの返信でお知らせください」（一斉送信） | reply_needed | 一斉送信でも、返信で答えることを求めている |
| 「お世話になっております。先日はありがとうございました。今後ともよろしくお願いします」 | uncertain | 礼儀として返すことはあるが、なくても困らない |
| 「鈴木さん、この件どう思いますか」（To: 鈴木、CC: 山田） | no_reply_needed | 質問は To の鈴木に向いている |
| 「皆さん、この件どう思いますか」（To: 鈴木、CC: 山田） | uncertain | CC の受信者も意見を求められているか分からない |

## モデルへの質問

上の基準を短くして `choice` 型の質問1つにした。実際に送る内容は [reply_question.json](../apps/reply-eval/reply_question.json)。
`probabilities` の3つの値（合計1）を、CSV の `p_reply_needed`・`p_no_reply_needed`・`p_uncertain` にする。

## 結果（2026-10-29）

数値の全体は [report.md](../apps/reply-eval/report.md)、全モデルを並べた Excel は [data/06_reply_comparison.xlsx](../apps/reply-eval/data/06_reply_comparison.xlsx)。

| モデル | 実行環境 | 正答率（95% 区間） | 「返信が必要」の適合率 | 「返信が必要」の再現率 | 「返信が必要」の F 値 | 3区分平均の F 値 | ROC AUC |
|---|---|---|---|---|---|---|---|
| Basal-Omni-1.0-Max | GPU | 91.7%（88.0〜94.3%） | 97.7% | 100.0% | 0.988 | 0.886 | 1.000 |
| Chon-1.0 | GPU | 91.0%（87.2〜93.7%） | 95.4% | 100.0% | 0.977 | 0.875 | 1.000 |
| H2O-Lightning-4B | GPU | 84.0%（79.4〜87.7%） | 90.9% | 96.0% | 0.934 | 0.753 | 0.991 |
| Laya | CPU | 37.7%（32.4〜43.3%） | 50.0% | 0.8% | 0.016 | 0.198 | 0.474 |

- **正解ラベルの揺れは小さい。** 生成時のラベルと、正解を伏せて別のエージェント（Sonnet）が付け直したラベルの一致率は 97.7%（κ 0.962）。食い違った7件は、どれも生成時「どちらとも言えない」を付け直しで「返信は不要」としたもの。
- **Basal と Chon は「返信が必要」をほぼ完全に見分ける。** 返信が必要な125件をどちらも全件拾い、ROC AUC は 1.000。誤りの大半は「返信は不要」と「どちらとも言えない」の境界（礼儀として返すかどうか）。
- **H2O は「どちらとも言えない」を「返信は不要」に寄せる。** この区分の再現率は 34.0%。「返信が必要」の判定は閾値を 0.8 に上げると F 値 0.951 になる。
- **Laya はこの課題を解けていない。** 「返信が必要な確率」は最大でも 0.50 で、300件のうち299件を「返信が必要」以外と判定した。ROC AUC 0.474 は当てずっぽうと変わらない。入力の切り詰めはなく、300件すべて multilingual チェックポイントで判定している。

### 結果を読むときの注意

- メールは架空で、判定基準に沿ってラベルがはっきり決まるように作った。実際の受信箱のメールより判断しやすい可能性が高い。
- 生成も付け直しも Claude 系のモデルが行ったため、人どうしで付けた場合より一致率が高く出ている可能性がある。
- 正答率の 95% 区間は Basal と Chon で重なっていて、この2つの差は 300 件では区別できない。
